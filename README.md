# 每日提醒与日程

Electron + HTML/CSS/JavaScript 的本地 Windows 桌面应用，数据保存在本地 SQLite 文件中，不需要登录或在线接口。

## 运行

```powershell
npm install
npm start
```

## 自动化测试

```powershell
npm test
```

当前测试覆盖重复日期展开、提醒实例生成、待办改期（含重复系列单次实例）、逾期查询、完成记录去重、提醒只触发一次/稍后提醒、导入回滚、历史搜索、重复系列范围修改和数据库持久化相关场景。

## Windows 打包

```powershell
npm run dist
```

打包输出到 `release/`。electron-builder 首次打包可能需要从 GitHub 下载签名/安装器工具；网络不可达时 `npm start` 仍可运行，但 exe 安装包未必能生成。

安装包为 x64 NSIS 安装器。当前没有代码签名证书，Windows 可能显示“未知发布者”提示。项目默认关闭可选的可执行文件资源编辑，以兼容部分 Windows 环境解压 electron-builder 缓存时的符号链接权限限制；因此使用 Windows 默认程序图标/版本资源。

### GitHub 自动更新发布

自动更新仅供正式安装版使用；开发模式和便携版不会检查在线更新。更新服务只下载程序，不上传用户数据。每台电脑的 SQLite 数据保持本地；每次开始安装更新前会先在数据库目录的 `backups/` 中生成备份，卸载程序也不会主动删除用户数据。完全退出程序后，提醒功能仍不保证运行。

1. 首次发布使用当前 `0.1.0` 作为安装基线；下一版先递增 `package.json` 与锁文件中的版本号（例如 `0.1.1`），运行测试并构建。
2. 用 `npm run dist` 生成安装器和 `latest.yml`（如有 `.blockmap` 一并保留），不要更改配置所生成的 artifact 名称。`--publish never` 只构建，不会自动上传或发布。
3. 在仓库创建与版本号一致的 tag，例如 `v0.1.1`，建立 GitHub **正式 Release**（不能是 Draft 或 Pre-release），上传安装器、`latest.yml` 和对应 blockmap 后再发布。公开仓库不需要、也不应把 GitHub token 写进客户端。
4. 用户安装的旧版本启动后会检查最新正式 Release；发现新版本时由用户选择下载，下载完成后确认重启安装。网络或 GitHub 不可达时，旧版本仍可照常使用。

当前仅完成本地更新流程和模拟测试；尚未创建首个 GitHub Release，也未做真实的旧版升级到新版验收。首次发布后应至少用两份不同版本的安装包验证检查、下载、重启安装及本机 SQLite 数据保留。

## 当前实现进度

- 已实现：今日概览和待办增删改/完成、月/周/日视图、SQLite 持久化、一次性和重复事项提醒、多个提醒时刻、提前提醒、重复系列修改/删除范围、历史搜索与完成率、逾期事项页、日历拖拽改期、导入校验与事务回滚、托盘图标、开机启动开关、主题/字体/字号/密度/布局/间距等样式设置。
- 仍待完善：重复规则的完整长期后续生成（当前无结束日期最多预生成 90 天/366 条）、完成记录与历史界面细节、托盘菜单的更多操作、安装包签名和逐项系统通知权限联调。
- 测试使用 `npm test` 和 `npm run test:electron`；Electron 更新集成测试使用模拟 updater，不访问 GitHub，也不实际安装更新。Windows 系统通知权限、托盘点击、开机启动、拖拽 UI 和真实跨版本更新仍需在目标 Windows 10/11 机器上手工验收。

## 数据和提醒说明

数据库路径为 Electron `app.getPath('userData')/daily-reminder.sqlite`。程序运行或最小化到托盘时会轮询提醒；完全退出后，第一版不保证触发提醒。
